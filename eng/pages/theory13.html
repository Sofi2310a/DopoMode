13 — Advanced OOP

You've already learned how to create classes, work with objects, and protect data using encapsulation.

But what happens when different classes need to share features or behave differently?

That's where Advanced Object-Oriented Programming (OOP) comes in!

In this lesson, you'll explore inheritance, polymorphism, virtual functions, abstract classes, and other tools that help developers build flexible C++ applications.

1. Inheritance

Imagine you're creating a game with warriors, archers, and mages.

All characters have common features, such as a name, but each character type has its own abilities.

Instead of repeating the same code, we can use inheritance.

Inheritance allows a new class to build on an existing class.

  • Base class — provides common features.
  • Derived class — inherits those features and can add its own.

Let's create a warrior character.

#include <iostream>
#include <string>

class Character {
public:
    std::string name;

    void introduce() const {
        std::cout << "I am " << name << "\n";
    }
};

class Warrior : public Character {
public:
    void attack() const {
        std::cout << "Warrior attacks!\n";
    }
};

int main() {
    Warrior player;

    player.name = "Alex";
    player.introduce();
    player.attack();

    return 0;
}

Output:

I am Alex
Warrior attacks!

How Does It Work?

The Warrior class inherits from Character using:

class Warrior : public Character

This means Warrior can use the public features of Character while adding new ones.

Here, introduce() comes from the base class, while attack() belongs to Warrior.

Remember: Inheritance helps you share behavior between related classes without duplicating code.

2. Types of Inheritance

C++ supports several forms of inheritance.

Type Description
Single One class inherits from one base class
Multilevel A derived class becomes the base for another class
Multiple A class inherits from several base classes
Hierarchical Several classes inherit from one base class

Let's look at hierarchical inheritance.

#include <iostream>

class Animal {
public:
    void breathe() const {
        std::cout << "Breathing...\n";
    }
};

class Dog : public Animal {
};

class Cat : public Animal {
};

int main() {
    Dog dog;
    Cat cat;

    dog.breathe();
    cat.breathe();

    return 0;
}

Output:

Breathing...
Breathing...

Both Dog and Cat inherit the breathe() function from Animal.

When Should You Use Inheritance?

Inheritance works best when classes have a meaningful "is-a" relationship.

For example:

A dog is an animal.

A warrior is a character.

However, inheritance isn't always the best choice. Sometimes combining objects is simpler, as you'll discover later in this lesson.

3. Polymorphism

Now imagine a game containing different animals.

Every animal can make a sound, but dogs bark and cats meow.

How can we call the same function and get different results?

We use polymorphism!

Polymorphism allows different object types to respond differently to the same operation.

#include <iostream>

class Animal {
public:
    virtual void makeSound() const {
        std::cout << "Animal makes a sound\n";
    }

    virtual ~Animal() = default;
};

class Dog : public Animal {
public:
    void makeSound() const override {
        std::cout << "Woof!\n";
    }
};

class Cat : public Animal {
public:
    void makeSound() const override {
        std::cout << "Meow!\n";
    }
};

int main() {
    Dog dog;
    Cat cat;

    Animal* animals[2] = {&dog, &cat};

    for (Animal* animal : animals) {
        animal->makeSound();
    }

    return 0;
}

Output:

Woof!
Meow!

Why Does This Work?

Both objects are accessed through pointers of type Animal*.

However, because makeSound() is virtual, C++ calls the version belonging to the actual object.

The dog barks, and the cat meows.

This behavior is called runtime polymorphism.

Remember: Polymorphism allows you to use a common interface while different objects provide their own behavior.

4. Virtual Functions

Virtual functions make runtime polymorphism possible.

A virtual function is a member function that derived classes can override to provide their own behavior.

We declare one using the virtual keyword.

#include <iostream>

class Vehicle {
public:
    virtual void start() const {
        std::cout << "Vehicle starts\n";
    }

    virtual ~Vehicle() = default;
};

class Car : public Vehicle {
public:
    void start() const override {
        std::cout << "Car engine starts\n";
    }
};

int main() {
    Car car;
    Vehicle* vehicle = &car;

    vehicle->start();

    return 0;
}

Output:

Car engine starts

What Do virtual and override Mean?

  • virtual — allows derived classes to customize behavior that is selected at runtime through a base-class pointer or reference.
  • override — tells the compiler that a derived function is intended to override an inherited virtual function.

The override keyword is especially useful because the compiler can detect mistakes in function names or parameter types.

Notice the virtual destructor in the base class:

virtual ~Vehicle() = default;

This is an important practice for polymorphic base classes, especially when derived objects might be destroyed through base-class pointers.

Remember: Virtual functions allow the correct derived-class behavior to be selected when working through base-class pointers or references.

5. Abstract Classes

Sometimes we want a class to define what its derived classes must do without providing every implementation.

For example, every shape should be able to calculate its area, but rectangles and circles use different formulas.

An abstract class helps us define this common requirement.

#include <iostream>

class Shape {
public:
    virtual double area() const = 0;

    virtual ~Shape() = default;
};

class Rectangle : public Shape {
private:
    double width;
    double height;

public:
    Rectangle(double w, double h)
        : width(w), height(h) {
    }

    double area() const override {
        return width * height;
    }
};

int main() {
    Rectangle rect(5, 3);

    std::cout << rect.area() << "\n";

    return 0;
}

Output:

15

What Makes a Class Abstract?

Look at this line:

virtual double area() const = 0;

The = 0 makes area() a pure virtual function.

Because Shape contains a pure virtual function, we cannot create a Shape object directly.

The Rectangle class provides an implementation of area(), making it possible to create rectangle objects.

Remember: Abstract classes define common interfaces that concrete derived classes can implement.

6. Operator Overloading

You've already used operators such as +, -, and ==.

But what if you create your own class and want those operators to work with its objects?

C++ allows you to define how existing operators behave with custom types. This is called operator overloading.

Let's create a class representing a point in two-dimensional space.

#include <iostream>

class Point {
public:
    int x;
    int y;

    Point(int xValue, int yValue)
        : x(xValue), y(yValue) {
    }

    Point operator+(const Point& other) const {
        return Point(x + other.x, y + other.y);
    }
};

int main() {
    Point p1(2, 3);
    Point p2(4, 5);

    Point result = p1 + p2;

    std::cout << result.x << ", "
              << result.y << "\n";

    return 0;
}

Output:

6, 8

How Does It Work?

The function:

Point operator+(const Point& other) const

defines how two Point objects are added.

It creates a new point by adding their coordinates.

So this:

Point result = p1 + p2;

works much like addition with ordinary numbers.

Operator overloading can make your classes more convenient, but the meaning of an operator should remain clear and predictable.

Remember: Operator overloading lets custom types work naturally with existing C++ operators.

7. Composition vs Inheritance

Not every relationship between classes should use inheritance.

Imagine a car and its engine.

A car has an engine, but a car is not an engine.

This relationship is better represented using composition.

Composition means building a class using objects of other classes.

#include <iostream>

class Engine {
public:
    void start() const {
        std::cout << "Engine started!\n";
    }
};

class Car {
private:
    Engine engine;

public:
    void startCar() const {
        engine.start();
    }
};

int main() {
    Car car;

    car.startCar();

    return 0;
}

Output:

Engine started!

The Car class contains an Engine object and uses its functionality.

What's the Difference?

Inheritance Composition
Represents an "is-a" relationship Represents a "has-a" relationship
Builds on a base class Combines objects
Shares an inherited interface or behavior Uses contained objects to provide functionality

Both approaches are useful, but composition is often more flexible when classes don't have a genuine inheritance relationship.

Remember: Use inheritance for meaningful type relationships and composition when one object contains another.
