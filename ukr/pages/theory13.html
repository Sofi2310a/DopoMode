13 — Поглиблене ООП

Ти вже навчився створювати класи, працювати з об’єктами та захищати дані за допомогою інкапсуляції.

Але що робити, коли різні класи повинні мати спільні можливості або по-різному виконувати ті самі дії?

Саме тут у пригоді стають складніші можливості об’єктно-орієнтованого програмування (ООП)!

У цьому уроці ти познайомишся з успадкуванням, поліморфізмом, віртуальними функціями, абстрактними класами та іншими інструментами, які допомагають розробникам створювати гнучкі застосунки на C++.

1. Успадкування

Уяви, що ти створюєш гру з воїнами, лучниками та магами.

Усі персонажі мають спільні характеристики, наприклад ім’я, але кожен тип персонажа володіє власними здібностями.

Замість того щоб повторювати однаковий код, можна використати успадкування.

Успадкування дозволяє створювати новий клас на основі вже наявного.

  • Базовий клас — надає спільні характеристики та поведінку.
  • Похідний клас — успадковує ці можливості та може додавати власні.

Створімо персонажа-воїна.

#include <iostream>
#include <string>

class Character {
public:
    std::string name;

    void introduce() const {
        std::cout << "I am " << name << "\n";
    }
};

class Warrior : public Character {
public:
    void attack() const {
        std::cout << "Warrior attacks!\n";
    }
};

int main() {
    Warrior player;

    player.name = "Alex";
    player.introduce();
    player.attack();

    return 0;
}

Вивід:

I am Alex
Warrior attacks!

Як це працює?

Клас Warrior успадковує клас Character за допомогою такого запису:

class Warrior : public Character

Це означає, що Warrior може використовувати публічні можливості класу Character та водночас додавати власні.

У цьому прикладі функція introduce() успадкована від базового класу, а attack() належить класу Warrior.

Пам’ятай: успадкування дозволяє використовувати спільну поведінку пов’язаних класів без дублювання коду.

2. Види успадкування

C++ підтримує кілька видів успадкування.

Вид Опис
Одиничне Один клас успадковує один базовий клас
Багаторівневе Похідний клас стає базовим для іншого класу
Множинне Один клас успадковує кілька базових класів
Ієрархічне Кілька класів успадковують один базовий клас

Розгляньмо приклад ієрархічного успадкування.

#include <iostream>

class Animal {
public:
    void breathe() const {
        std::cout << "Breathing...\n";
    }
};

class Dog : public Animal {
};

class Cat : public Animal {
};

int main() {
    Dog dog;
    Cat cat;

    dog.breathe();
    cat.breathe();

    return 0;
}

Вивід:

Breathing...
Breathing...

І Dog, і Cat успадковують функцію breathe() від класу Animal.

Коли варто використовувати успадкування?

Успадкування найкраще підходить тоді, коли між класами існує змістовний зв’язок типу «є різновидом».

Наприклад:

Собака — це тварина.

Воїн — це персонаж.

Проте успадкування не завжди є найкращим рішенням. Іноді простіше поєднати кілька об’єктів. Про такий підхід ти дізнаєшся наприкінці уроку.

3. Поліморфізм

Тепер уяви гру, у якій є різні тварини.

Кожна тварина може видавати звуки, але собаки гавкають, а коти нявкають.

Як викликати одну й ту саму функцію, але отримати різні результати?

Для цього існує поліморфізм!

Поліморфізм дозволяє об’єктам різних типів по-різному реагувати на ту саму операцію.

#include <iostream>

class Animal {
public:
    virtual void makeSound() const {
        std::cout << "Animal makes a sound\n";
    }

    virtual ~Animal() = default;
};

class Dog : public Animal {
public:
    void makeSound() const override {
        std::cout << "Woof!\n";
    }
};

class Cat : public Animal {
public:
    void makeSound() const override {
        std::cout << "Meow!\n";
    }
};

int main() {
    Dog dog;
    Cat cat;

    Animal* animals[2] = {&dog, &cat};

    for (Animal* animal : animals) {
        animal->makeSound();
    }

    return 0;
}

Вивід:

Woof!
Meow!

Чому це працює?

Доступ до обох об’єктів здійснюється через вказівники типу Animal*.

Однак оскільки функція makeSound() є віртуальною, C++ викликає її версію, яка відповідає фактичному типу об’єкта.

Тому собака гавкає, а кіт нявкає.

Така поведінка називається поліморфізмом часу виконання.

Пам’ятай: поліморфізм дозволяє використовувати спільний інтерфейс, водночас кожен тип об’єкта може реалізовувати власну поведінку.

4. Віртуальні функції

Віртуальні функції забезпечують поліморфізм часу виконання.

Віртуальна функція — це функція-член базового класу, яку похідні класи можуть перевизначати, щоб реалізувати власну поведінку.

Для її оголошення використовують ключове слово virtual.

#include <iostream>

class Vehicle {
public:
    virtual void start() const {
        std::cout << "Vehicle starts\n";
    }

    virtual ~Vehicle() = default;
};

class Car : public Vehicle {
public:
    void start() const override {
        std::cout << "Car engine starts\n";
    }
};

int main() {
    Car car;
    Vehicle* vehicle = &car;

    vehicle->start();

    return 0;
}

Вивід:

Car engine starts

Що означають virtual та override?

  • virtual — дозволяє похідним класам перевизначати поведінку, яку буде вибрано під час виконання програми через вказівник або посилання на базовий клас.
  • override — повідомляє компілятору, що функція похідного класу має перевизначати успадковану віртуальну функцію.

Ключове слово override особливо корисне, оскільки компілятор може виявляти помилки в назвах функцій або типах їхніх параметрів.

Зверни увагу на віртуальний деструктор базового класу:

virtual ~Vehicle() = default;

Це важлива практика для поліморфних базових класів, особливо якщо об’єкти похідних класів можуть знищуватися через вказівники на базовий клас.

Пам’ятай: віртуальні функції дозволяють викликати відповідну реалізацію похідного класу під час роботи через вказівники або посилання на базовий клас.

5. Абстрактні класи

Іноді нам потрібно, щоб клас визначав, які дії повинні виконувати його похідні класи, але не надавав реалізацію кожної з цих дій.

Наприклад, кожна геометрична фігура повинна вміти обчислювати свою площу, але прямокутник і коло використовують різні формули.

Таку спільну вимогу можна визначити за допомогою абстрактного класу.

#include <iostream>

class Shape {
public:
    virtual double area() const = 0;

    virtual ~Shape() = default;
};

class Rectangle : public Shape {
private:
    double width;
    double height;

public:
    Rectangle(double w, double h)
        : width(w), height(h) {
    }

    double area() const override {
        return width * height;
    }
};

int main() {
    Rectangle rect(5, 3);

    std::cout << rect.area() << "\n";

    return 0;
}

Вивід:

15

Що робить клас абстрактним?

Зверни увагу на цей рядок:

virtual double area() const = 0;

Запис = 0 робить area() чистою віртуальною функцією.

Оскільки клас Shape містить чисту віртуальну функцію, ми не можемо безпосередньо створити об’єкт типу Shape.

Клас Rectangle надає реалізацію функції area(), тому можна створювати об’єкти прямокутників.

Пам’ятай: абстрактні класи визначають спільні інтерфейси, які можуть реалізовувати конкретні похідні класи.

6. Перевантаження операторів

Ти вже використовував оператори +, - та ==.

Але що робити, якщо ти створив власний клас і хочеш, щоб ці оператори працювали з його об’єктами?

C++ дозволяє визначати поведінку наявних операторів для власних типів даних. Це називається перевантаженням операторів.

Створімо клас, який представляє точку у двовимірному просторі.

#include <iostream>

class Point {
public:
    int x;
    int y;

    Point(int xValue, int yValue)
        : x(xValue), y(yValue) {
    }

    Point operator+(const Point& other) const {
        return Point(x + other.x, y + other.y);
    }
};

int main() {
    Point p1(2, 3);
    Point p2(4, 5);

    Point result = p1 + p2;

    std::cout << result.x << ", "
              << result.y << "\n";

    return 0;
}

Вивід:

6, 8

Як це працює?

Функція:

Point operator+(const Point& other) const

визначає, як додавати два об’єкти типу Point.

Вона створює нову точку, додаючи відповідні координати двох точок.

Тому цей запис:

Point result = p1 + p2;

працює подібно до звичайного додавання чисел.

Перевантаження операторів може зробити використання власних класів зручнішим, але значення оператора має залишатися зрозумілим і передбачуваним.

Пам’ятай: перевантаження операторів дозволяє власним типам даних природно працювати з наявними операторами C++.

7. Композиція та успадкування

Не кожен зв’язок між класами варто реалізовувати через успадкування.

Уяви автомобіль і його двигун.

Автомобіль має двигун, але автомобіль не є двигуном.

Такий зв’язок краще представляти за допомогою композиції.

Композиція означає створення класу, який містить об’єкти інших класів.

#include <iostream>

class Engine {
public:
    void start() const {
        std::cout << "Engine started!\n";
    }
};

class Car {
private:
    Engine engine;

public:
    void startCar() const {
        engine.start();
    }
};

int main() {
    Car car;

    car.startCar();

    return 0;
}

Вивід:

Engine started!

Клас Car містить об’єкт Engine і використовує його функціональність.

У чому різниця?

Успадкування Композиція
Представляє зв’язок «є різновидом» Представляє зв’язок «має у своєму складі»
Створює новий клас на основі базового Поєднує об’єкти різних класів
Використовує успадкований інтерфейс або поведінку Використовує функціональність об’єктів, які входять до складу класу

Обидва підходи корисні, але композиція часто є гнучкішою, коли між класами немає справжнього зв’язку успадкування.

Пам’ятай: використовуй успадкування для змістовних зв’язків між типами, а композицію — коли один об’єкт містить інший.
